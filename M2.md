# M2 · HTTP API v1

Implementation and review checklist for [Milestone 2](https://github.com/bobby/rescrow/milestone/2).
The scope is the seven linked issues, rather than all future endpoints sketched
in DESIGN §8. Claims, signed receipts, events, and enterprise infrastructure
remain in their later milestones.

- [x] **#24 — HTTP entrypoint:** Axum/Tower composition, selectable authority,
  request IDs, deadlines, body limits, graceful draining of actual writes, and
  socket-level memory integration tests. Preserve the default local dependency
  boundary.
- [ ] **#25 — Contract:** OpenAPI 3.1, metadata/observation separation, canonical
  decimal quantities, millisecond timestamps, keyset pagination and filtering,
  links and serving metadata, privileged resource creation. Contract fixtures
  and server checks in CI are implemented. Human contract review and merge remain the completion gate.
- [x] **#26 — Idempotency:** credential-scoped namespace and UUIDv7 keys, normalized
  operation/expiration/context digests, duplicate-key rejection, published
  vectors, new/replay/processing status semantics, current authorization on
  replay, and bound actual-delta decisions.
- [x] **#27 — Problems:** an exhaustive Application-code/status/problem table,
  request and transaction identities, explicit retryability and unknown-outcome
  behavior, including bounded internal retries.
- [x] **#28 — Identity:** pluggable workload authentication, pinned asymmetric JWT
  algorithms/issuer/audience/expiry, endpoint and resource grants, tenant
  isolation, and bounded persisted authorization facts without bearer tokens.
- [x] **#29 — Admission:** configurable body/participant/numeric/context/pending
  limits; atomic tenant/credential hold accounting; per-tenant rates and
  bounded separate admission/decision/recovery lanes, with decisions protected
  when admission overloads.
- [x] **#30 — Clients:** feature-gated remote CLI with matching outputs, a Rust
  client retaining identical requests through deadlines/jitter/explicit-endpoint
  fallback, and reproducibly generated Python/TypeScript clients with examples
  and smoke tests.

M1 (#58) is merged. M2 targets main and is ready for a separate contract/code review after CI passes. No regional or enterprise backend is added.

Evidence:

- `cargo test --workspace --all-features --locked`: all existing safety, concurrency, crash and local CLI tests pass alongside the new authorization, quota, HTTP and client tests.
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings` and `cargo fmt --all -- --check` pass.
- Real socket tests cover current authorization on every endpoint/replay, tenant/namespace isolation, 201/200 races, frozen rejections, canonical digests, duplicate JSON, pagination, limits and separate traffic lanes.
- Delayed-publication tests distinguish confirmed durable 202 from unconfirmed 503 and prove shutdown drains actual writes after request cancellation.
- Executable tests select existing file or disposable memory, verify TLS and SIGTERM, and confirm the file authority generation persists across reopen.
- Rust lost-response tests compare the exact retried key and bytes and confirm a single hold. Alternate endpoints require the same pinned actual authority.
- CI enables real-server Python/TypeScript and remote CLI lifecycle smokes, regenerates clients from OpenAPI, checks TypeScript, and validates both checked-in and freshly captured responses against OpenAPI 3.1.
- Default CLI normal dependencies contain no Tokio, HTTP client/server or cloud SDK; Domain remains dependency-free.

[API.md](API.md) records the complete wire contract, configuration, defaults, limits, problem table and verification commands. File schema 4 is an intentional pre-release format change with no migration. Pagination currently bounds responses, not underlying inspection scan cost. Rates/traffic queues are process-local; outstanding-hold quotas are atomic across instances sharing the authority.
